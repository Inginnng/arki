# 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| `127.0.0.1` 拒绝连接 | 重新运行启动器，打开其输出的地址。电脑重启后需要重新启动；没有系统开机服务。 |
| 后台启动失败 / Codex 不可用 | 检查 `node --version`、Codex 登录和可执行文件。先在终端验证一次普通 Codex 请求。不要把密钥粘贴进 Issue。 |
| 分析或问答超时 | 检查 Codex 服务、网络/代理与额度。保留问题后重试，复制界面诊断中的请求 ID；大型项目可缩小问题范围。 |
| AI 结果未被接受 | 查看诊断中具体的证据、对象或字段问题。旧图会保留；过期代码需重新分析。排版失败本身不应丢弃语义结果。 |
| 图还是旧样式 / 新版本未生效 | 确认结束旧后台并启动新版本，再刷新页面。启动器会复用同一项目的已运行后台。 |
| 看不到上次分析 | 使用相同浏览器、项目与端口；检查是否清理过站点数据或切换隐私窗口。重要内容应定期导出。 |
| 检查更新失败 | 不影响阅读。确认 GitHub 连通性；限流后稍等再试，或直接访问 Releases。失败不会显示“已是最新版”。 |
| 有源码变更 / 存档过期 | 旧分析可阅读，重新生成后再进行基于当前代码的修改。 |
| 本地导入 MD 无法提问 | 导入用于本地阅读。需要项目证据时用「从项目添加」。 |
| “同一任务上下文”不可用 | 当前宿主未证明精确任务绑定时会降级。架构工作台本来就使用项目证据，不依赖当前任务历史。 |

报告问题时附上：Arki 版本、操作系统、安装方式、复现步骤、预期与实际结果、可公开的最小示例和脱敏诊断。见 [Bug 模板](https://github.com/Inginnng/arki/issues/new?template=bug_report.yml)。
