# 检查和安装更新

## 检查版本

点击工作台右上角的版本号，再点击「检查更新」。Arki 查询 [本仓库的正式发行版](https://github.com/Inginnng/arki/releases/latest)：有新版本时显示发行说明与下载链接，当前版本较新、尚无公开版本、GitHub 限流和网络错误会分别说明。

检查由用户触发。只请求公开版本元数据，不上传项目内容、不使用 GitHub 账号凭据、不自动下载、执行或重启。成功结果缓存 10 分钟，失败缓存 1 分钟，网络超时为 10 秒；草稿和预发布版本不作为正式更新。版本比较按主、次、补丁数字进行。

## 发行包用户

1. 在发行说明中确认变化和兼容性，导出重要分析。
2. 下载新的 ZIP 和 `SHA256SUMS.txt`，核对哈希。
3. 解压到新的版本目录，保留旧版本以便回退。
4. 结束旧 Arki 后台后，从新目录运行同一个项目和端口。Windows 可在任务管理器按完整命令行识别 `dist/arki.mjs --serve` 的启动器与其 `web-server.mjs` 子进程；不要停止无关 Node 进程。也可重启电脑后启动新版本。
5. 刷新原有工作台地址，检查右上角版本。若提示前后端版本不一致，先确认旧后台已经退出。

Arki 目前没有自动安装器。启动器会复用同一项目的已有后台，因此仅下载新版本不会替换正在运行的服务。

## 源码用户

在 Arki 仓库中先确认 `git status`，保留你的修改；然后：

```sh
git pull --ff-only
pnpm install --frozen-lockfile
pnpm build
```

按上面的方式结束旧后台，重新 `pnpm start`。不要在**被分析项目**目录运行这些更新命令。

## Codex 插件用户

更新注册的源码目录并完成构建后，再执行：

```sh
codex plugin add aimd-reader@aimd-local
```

如使用 Git marketplace，先按 `codex plugin marketplace upgrade --help` 更新对应来源。重启 Codex 或打开新任务以加载新缓存。版本使用独立缓存目录，避免覆盖 Windows 正在使用的插件文件。

## 保存与回退

浏览器存档不放在 Arki 安装目录，但与浏览器站点地址绑定。保持同一项目、浏览器和端口有助于继续读取。端口变化会使原存档在新地址不可见；回到原地址或使用之前导出的文档。新版本写入的数据不保证被更老版本完整理解，回退前保留导出。
