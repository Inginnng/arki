# 使用指南

## 从结构到行为

「架构分析图」用大框、小框表达子系统和组件归属。名称描述职责，原始代码标识作为辅助信息。点击组件可查看职责、接口和来源，并提出具体问题，例如“这里如何校验输入？”

「流程图」复用同一组件布局。选择正常操作、缓存命中、异常处理等有证据支持的场景后，参与组件会突出显示，其他组件淡化。同一组件可以出现多个步骤；数字用于定位，不意味着所有分支依次执行。

右侧显示当前步骤的输入、处理、输出与代码来源。沿「继续」进入后续步骤；条件分支分别选择，并行路径分别阅读。「上一步」返回本次阅读路径，「回到入口」回到场景起点。组件内转移保留在步骤和传递列表中，不需要人为画成跨组件连线。

这是一种源码导览，不是运行时追踪器或执行模拟器。AI 只保留本次代码证据支持的场景，不保证覆盖系统所有路径。出现“待核对”时，先查看缺失条件或来源，再补充提问。

## 问答与修改

选中组件、子系统或关系后提问。可选择解释、相关范围或整图完善；流程步骤的提问包含当前场景上下文。成功的修改保留历史，可撤销、重做。源码变化会提示分析过期；重新生成成功前保留旧图。

来源按钮会打开文件和对应行。问答中的证据快照代表当时读取到的代码；当前代码可能已变化。布局失败时仍能阅读组件目录、步骤与传递列表，不必为排版问题重新消耗一次 AI 分析。

## 文档工作台

「从项目添加」选择需要阅读的 Markdown；「导入 MD」导入 UTF-8 `.md` / `.markdown` 文件，每个不超过 2 MB。移除工作台条目不会删除源文件。

导入文档用于本地阅读。需要项目问答时，从项目添加文档；文档侧问答按入口选择 Codex 任务，架构分析本身使用项目证据，不宣称继承当前任务历史。

独立的 reviewed-document / MCP 阅读器还提供精确 diff 审核：只有批准绑定的源文件与差异后，才能创建新的 `*.explained.md`。原始文档不覆盖。

## 保存、离线与导出

架构、已完成的问答和工作台集合按项目存于当前浏览器。生产页面成功加载一次后可缓存页面外壳；后台暂不可用时仍可阅读已保存分析和证据。新的 AI 问答及查看当前源码需要本地后台。

清理浏览器数据会删除本地存档。不同浏览器或端口拥有不同的存储空间，因此建议导出重要分析。MD 和离线 HTML 包含所有场景、步骤、关系和来源；HTML 为无脚本的静态导出，不具备工作台的 AI 问答能力。

分享导出前检查其中的代码片段、相对路径和项目信息是否适合公开。
